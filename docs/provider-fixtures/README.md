# Provider Fixture 目录

本目录只保留说明文档。Provider 运行时身份以 `assets/contract/provider-registry.json` 为准；产品覆盖要求位于 `assets/contract/server-provider-requirements.json`，兼容窗口内的最小 preset fixture 位于 `assets/contract/provider-legacy-compatibility.json`。这些文件均由本仓库维护，不从外部工作树生成。

约束：

- 新增结构只按 Server reader、writer 和 runtime contract 的实际需求补充，并在 review 中说明消费路径。
- fixture 用于 adapter contract test、provider type 分类回归、usage parser snapshot。
- OAuth/账号型 provider 没有真实凭据时，只能保存脱敏配置结构和协议样例，不能标记真实登录能力完成。

OpenAI OAuth/Codex 的当前可执行协议样例保存在 `assets/contract/openai-oauth-protocol.json`。它固定官方 OAuth/上游地址、CLI callback、workspace header、可信 claim 合并样例和 WebSocket fallback 边界；Rust 单测直接消费 identity 与 fallback status 样例，修改实现或证据时必须同步更新并 review。

Codex 的一次性外部差异基线保存在 `assets/contract/codex-reference-delta.json`。append-only schema v2 以独立 digest 固定原 v1 的 `policy`、`sources`、`capabilities`、`incrementalEnhancements`、`realAcceptance`、`wireGoldens` 六个字段，追加 `CLIProxyAPI`、`codex2api` 两个干净只读 source snapshot、9 个 source delta 和 13 条不可变 observation；每条 observation 都绑定 source commit/tree/path/symbol/digest、处置以及本仓库 committed target baseline/implementation object。它固定 Unicode schema/纯 const union、Responses HTTP/SSE/WS error/sequence/首尾帧、具名 tool output 与 WS→HTTP pre-commit 边界；同时把 GPT Image 2.5 三个 variant、WS prewarm 和后续图片 quota/cache 明确保持为四个独立 `live_pending` 门禁。`scripts/smoke/codex-real-receipt.mjs` 只接受仓库外私有、绑定 target commit/Account generation/Provider/Share/model 的 operation receipt；loopback fixture 不能提升真实状态，付费 `codex-images-real.mjs` 也只是 `probe_only`。默认审计自包含，只读取本仓库及其已提交 Git object；`node scripts/audit/audit-codex-reference-delta.mjs --check-sources` 才会按冻结 commit、tree 和 SHA-256 可选复核外部已提交对象。

Cursor 的一次性外部差异基线保存在 `assets/contract/cursor-reference-delta.json`。append-only schema v2 以独立 digest 固定原 v1 的全部十个历史字段，新增一个绑定 OmniRoute `02c663cdd0e8577bdcf2b01a44046bcd46dc6a7a` commit/tree 且明确排除 22 项工作树改动的 source snapshot，以及映射 CUR-01～03、CUR-N1/N2、CORE-N1、LIVE-N1 的 7 条不可变 observation。合同冻结 ServerConfig/interaction 未知字段、重复字段失败关闭、Connect 分帧与 partial EOF、终态 envelope 和完整 fresh `*-fast` 模型 ID；每条 observation 还绑定 committed source path/symbol/digest 与本仓库 target baseline/implementation object。`scripts/audit/audit-cursor-reference-delta.mjs` 默认只检查本地合同和本仓库已提交对象，`--check-sources` 才按 SHA-256 复核只读外部 object。`scripts/smoke/cursor-real.mjs` 一次只验收 OAuth 或 API-key rail，并只接受仓库外 `0600` 私密 receipt；receipt 以 scope/binding digest 代替原始标识，同时绑定 target commit、harness revision、credential generation、body hashes、测量与恢复决策。loopback fixture 不会把任一 rail 升级为 live verified。

Antigravity 的外部差异基线保存在 `assets/contract/antigravity-reference-delta.json`。schema v2 原样保留 v1 的 `CLIProxyAPI` reasoning replay、schema subset、transport scope、compaction 风险证据和 `Antigravity-Manager` conversation session 样本，并追加不可变 observation ledger，映射 source commit/tree/digest、处置、target baseline、implementation commit 与 fixture。默认审计只检查本仓库，`node scripts/audit/audit-antigravity-reference-delta.mjs --check-sources` 才按 SHA-256 读取外部已提交 Git object。`scripts/smoke/antigravity-real.mjs` 对 `antigravity_oauth`、`agy_oauth` 分开接受仓库外私有 receipt；fixture 只能证明 harness contract。AG-01..03 为本地 `fixture_verified`；两条 rail 与 AG-04 compaction 仍为 `live_pending`，compaction 运行时固定关闭。

Grok 的一次性外部差异基线保存在 `assets/contract/grok-reference-delta.json`。它只读取 `grok2api@8913b53fe92307a6f111b2885ab298a43c74a9ba` 的七个已提交 Git object，并记录 reasoning replay/recovery 与 root-union 的八个历史 commit；外部工作树和 `sub2api` 路由实现均不进入依赖。默认审计只检查本仓库，`node scripts/audit/audit-grok-reference-delta.mjs --check-sources` 才按 SHA-256 复核外部 object。GR-01..03 为本地 fixture verified；推理、媒体与 remote compaction receipt 分离，GR-04/05 在真实输入缺失时保持 `live_pending`，remote compaction 的运行时开关固定关闭。

Claude OAuth 的当前脱敏 wire capture 保存在 `assets/contract/claude-oauth-wire-profile.json`。它只保留 Claude Code/Stainless/Node/Axios 公开版本、endpoint identity family、token endpoint 顺序、billing fingerprint/CCH/beta 合同、静态模型 ID，以及不含账号或业务内容的合成 CCH golden body；token、账号标识、真实/原始请求响应 body 与未验证的私有 build metadata 明确排除。Rust 的 `ClaudeWireProfile`、Messages/CountTokens beta 矩阵、profile/bootstrap/roles 请求身份和静态模型目录以该 capture 为共同证据，任一项变化都必须同步更新 fixture、实现、测试和 `PROTOCOL_EVIDENCE.md`。

Claude Max 20x 的本地 resolver 测试包含脱敏的 `default_claude_max_20x` 协议形状；5x 仅有同形解析规则。两者都不是 live credential evidence；`scripts/smoke/claude-oauth-real.mjs` 只提供 probe，仍必须分别通过 `scripts/smoke/claude-real-receipt.mjs` 的 operation-scoped 私有 receipt gate 才能标记真实通过。
